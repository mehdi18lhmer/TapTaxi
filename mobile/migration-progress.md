# TapTaxi native implementation

Native iPhone and Android is the confirmed delivery target. The existing web app remains usable while its workflows are implemented with React Native views and platform navigation. All feature screens are classified nativize-now; no WebView shell is needed because the original web app remains independently runnable throughout the migration.

- [x] Foundation: Expo Router native stacks/tabs, source palette/fonts, persistent native storage, shared integer-centime model.
- [x] Driver: home, fare keypad, QR, connected and received states.
- [x] Wallet: balances, withdrawals, payout code, owner payment settings, history, statements, fuel, offers.
- [x] Account: notifications, preferences and help.
- [x] Passenger (2026-11-20): payment detail `transaction/[id]`, checkout `pay/[id]` (verify taxi, tip, test card / wallet, processing), receipt `receipt/[id]`, `my-payments`, `expired/[id]`, camera QR scanner `scan` with typed-code fallback. Rules in `src/lib/checkout.ts` and `src/lib/qr.ts`, with tests.
- [x] Onboarding (2026-11-20): `welcome`, `sign-in` (Moroccan number), `sms` (demo code 123456), `documents` (native file picker, files checked then dropped; also opened from Profil), `payout-setup`, `verification`. Rules in `src/lib/onboarding.ts`, with tests. The web splash is replaced by the native splash screen.
- [x] Native integrations: clipboard, haptics, camera, PDF creation/share, document picker.
- [x] Roles (2026-11-20): first screen `choose-role` ("Je suis chauffeur / passager"), saved on the device (`src/lib/role-store.tsx`, rules in `src/lib/roles.ts`). Root stack uses `Stack.Protected`: driver screens for drivers, `passenger` home for passengers, payment/receipt/scan/help shared. Switch role from either profile; "Se déconnecter" returns to the choice.
- [x] Passenger account (2026-11-20): login `passenger/login` (first name + Moroccan phone) and `passenger/code` (demo SMS 123456); home with default card; `passenger/profile`; `passenger/cards` and `passenger/add-card`. Saved cards keep only brand, last 4, expiry and holder (never the full number or CVV), stored on the device (`src/lib/passenger-store.tsx`, rules in `src/lib/passenger.ts` with tests). Checkout pre-selects the default card for one-tap payment and can save a new card. Test cards: 4242 4242 4242 4242, 5555 5555 5555 4444. Real version: cards tokenized by the payment provider, account on the server.
- [x] Brand & passenger nav (2026-11-20): official wordmark in `assets/logo/` (`wordmark.png`, `wordmark-light.png` for dark backgrounds, made transparent from the supplied PNG) used by `Logo`; web app and admin use `public/logo/`. Passenger tab bar `(passenger)`: Accueil `/passenger`, Scanner `/scan`, Reçus `/receipts`, Profil `/account`. App icon and splash still use the old "T." mark: a square version of the logo is needed.
- [x] Demo interface spec (2026-11-22, `TapTaxi_Demo_Interface_Spec.docx`):
  - Fees: 0–3 MAD by day by meter fare, +0,50 MAD at night (20:00–06:00); driver earns 10 % of the fee on digital payments (`FEE_TIERS`, `serviceFee`, `paymentBreakdown` in the shared `src/lib/model.ts`, also used by the web app). Table screen `fees`.
  - Payment methods at checkout `pay/[id]`: TapTaxi balance, saved card, Apple Pay (iOS) / Google Pay (Android, web), cash (recorded as `kind: 'cash'`, no fee, no wallet credit). Tips 2 / 5 / 10 MAD. Fare check against the request's estimate. Split between 2–4 people (one payment and one driver SMS per share, fee on each share). Driver SMS are derived from payments (`paymentSms`).
  - Passenger: request a taxi within 1 km on a Casablanca map (`passenger/request` → `passenger/ride/[id]`, simulated driver), wait & return, bookings for airport/stations/hotels (`passenger/book`, reminder 1 h before), wallet (`passenger/wallet`, `passenger/topup` by card or cash agent code), gift a ride (`passenger/gift`), notifications, ride history tab « Courses » → `passenger/trip/[id]` → « Signaler un problème ».
  - Driver tabs: Accueil · Portefeuille · Courses (incoming requests, bookings, demand) · Assistant · Profil. Relevés moved to `statements`, support to `help`. Ride flow `job/[id]` → `amount?ride=` (meter pre-filled) → QR. Earnings dashboard `earnings`, owner–driver link and shared history in `owner`, CNSS/AMO `coverage`.
  - AI (scripted demo): Darija assistant (`lib/assistant.ts`, tab `assistant`, simulated voice input, answers read aloud with `expo-speech`, confirmation card before any payment); demand prediction (`lib/demand.ts`, screen `demand`); multilingual support agent (`lib/support-agent.ts`, `passenger/support-chat`; refunds, disputes and safety open a ticket for a person).
  - Positioning screen `why` (from role choice and profiles).
  - Rules: `lib/rides.ts`, `lib/fare.ts`, `lib/places.ts`, `lib/passenger-wallet.ts`, `lib/coverage.ts`, `lib/ledger.ts`; tests in `lib/features.test.ts`. Rides/bookings persist under `taptaxi.native.rides.v1`; the demo ledger key moved to `taptaxi.native.demo.v3` (new sample data with cash rides and a month of history).
  - Open questions, demo choices: cash rides pay no fee; radius 1 km; wait & return priced on the meter (15 min included in the estimate); owner gets a fixed daily amount set by the driver in « Versement propriétaire »; CNSS/AMO partner, AI provider and Darija speech recognition not chosen (voice input simulated, scripted answers); Taxi Sahbi column shows « À confirmer ».
- [ ] Validation (open: TypeScript, lint and logic tests pass; iOS simulator checked; Android, `expo-doctor` and store exports not run yet): shared model tests, TypeScript, Expo dependency check, iOS/Android exports and simulator runtime checks.

Backend: the existing app has no server; both apps keep explicit local-demo boundaries. Real authentication, multi-device payment sessions, payment processing, withdrawals and identity checks require connected services. Local financial state is not treated as production accounting. Store publishing is outside this implementation request.

## Code layout

- `src/app/` — routes only. `_layout.tsx` groups them by role (driver / passenger / shared). Each file is a one-line re-export of a screen; stack titles live in `src/app/_layout.tsx`.
- `src/features/<area>/` — one screen per file: `driver/` (home, fare keypad, QR, received, payment detail), `passenger/` (home, scan, receipts, profile tabs; login, cards, checkout, receipt, expired), `onboarding/` (welcome → verification), `wallet/` (wallet, withdraw, owner payout, history, statements), `account/` (profile, settings, notifications, services, fuel advance, help).
- `src/components/` — shared UI (`ui.tsx`, transaction list, payout options).
- `src/lib/` — logic, no UI: `model.ts` (re-exports the shared web model), `ledger.ts` (native business rules: daily goal, owner payout, fuel advance, history filter, monthly statement), `store.tsx` (persisted state), `haptics.ts`, `ids.ts`, `pdf.ts`.
- Screens never build transactions or compute totals inline — add a function to `lib/ledger.ts` instead.
- Format with `../node_modules/.bin/prettier --write "src/**/*.{ts,tsx}"` (config in `.prettierrc`).
