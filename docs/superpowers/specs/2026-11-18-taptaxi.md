# TapTaxi application design

Implement the 30 supplied HTML screens as an interactive, phone-first web application. Preserve the source's red #D91E24, charcoal #121212, cream #F5F4F2, rounded cards, Inter/Space Grotesk, French copy and Arabic supporting labels. Desktop adds a useful navigation rail and spacious content while mobile retains the floating bottom navigation.

Approach: React + TypeScript + Vite, shared components and a persistent local demo ledger. This gives an immediately runnable app from the only existing input, an HTML design board. Native applications would require a separately chosen delivery platform. No existing backend or payment credentials are supplied.

Scope: driver dashboard, amount keypad, real QR rendering, payment waiting/connected/success states, wallet, validated withdrawals and withdrawal codes, monthly statements and PDF export, fuel advance demo, searchable history, notifications, profile preferences, owner payment settings, service offers; passenger verification, tips, card/wallet demo checkout, processing, receipts, payment history and expired codes; welcome, demo phone verification, local document selection, payout choice and review status.

Use integer centimes for all money. Credit a payment once; reject expired/cancelled requests; validate balances before withdrawals. Keep demo data in versioned localStorage with safe fallback and cross-tab updates. Never persist card details or document files. Label the local simulation; real transfers, identity verification, SMS, automatic owner scheduling and financial offers require backend/partner integrations. QR demonstration works in this browser; it is not a shared payment server.

Validation: business tests for money, single credit, expiry, cancellations, tips and withdrawal limits; production compilation; browser checks of complete driver/passenger, withdrawal, onboarding and navigation flows at desktop and mobile widths.
