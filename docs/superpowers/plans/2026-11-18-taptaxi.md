# TapTaxi Implementation Plan

**Goal:** Turn the supplied 30-screen HTML design into a polished interactive application.
**Architecture:** Shared React components and responsive shell, feature screens, a typed local ledger with integer centimes and demo adapters. Hash routes make passenger checkout and receipts addressable.
**Tech stack:** React, TypeScript, Vite, Lucide, QRCode, jsPDF, Vitest.
**Spec:** docs/superpowers/specs/2026-11-18-taptaxi.md

## Constraints

Preserve the supplied design and original HTML. Make demo boundaries clear. No external money movement, SMS or identity verification without integrations. Do not store sensitive checkout/document contents.

## Review focus

Duplicate payment submission must credit once. Expired/cancelled requests cannot pay. Invalid and excessive withdrawals cannot reduce balance. Corrupt browser data must recover. Narrow screens and keyboard users must reach all controls.
